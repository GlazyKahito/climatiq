# CLIMATIQ developer guide

Conventions every contributor (human or agent) follows. Read `docs/ARCHITECTURE.md` first.

## Running
- Dev server: `npm run dev` → embedded PostgreSQL 18 (port 54330, data in `.data/pg`) + migrations + demo seed + `next dev` on **http://localhost:3100**.
  The lead keeps one dev server running — **do not start a second one or kill it**. It hot-reloads your changes.
- Live build tracker: http://localhost:3100/progress (`node scripts/progress.mjs set <id> <todo|doing|done|blocked> "note"` / `log "msg"`).
- Tests: `npx vitest run` (unit + integration on in-memory PGlite via `tests/helpers/db.ts`). Typecheck: `npx tsc --noEmit`.
- Ad-hoc DB access from scripts: `node --env-file=.env.local --import tsx your-script.ts` and use `drizzle(new Pool({ connectionString: process.env.DATABASE_URL }), { schema })`.

## Next.js 16 specifics (bundled docs: `node_modules/next/dist/docs/`)
- `params` / `searchParams` are **Promises**: `export default async function Page({ params }: PageProps<'/forecasts/[code]'>) { const { code } = await params; }`. `LayoutProps<'/'>`, `RouteContext<'/api/x/[id]'>` are global helpers.
- `cookies()` / `headers()` are async. Middleware is now **`src/proxy.ts`** (optimistic redirects only).
- Route handlers are not cached by default. Server Actions live in `src/app/actions/*` or co-located `actions.ts` with `'use server'`.

## Layering
- `src/server/**` — business logic, DB access, adapters. Import `'server-only'` in files that read cookies/env/getDb. Prefer functions that take `db: DB` as the first argument (testable with PGlite).
- `src/app/**` — routing, server components (fetch data, check auth), client components for interactivity.
- `src/components/**` — presentational UI. No DB/env access.
- `src/lib/**` — client-safe shared constants/helpers (`domain.ts`, `rbac.ts`, `nav.ts`, `utils.ts`).

## Auth & authorisation (server-side, always)
- Pages: `const user = await requirePagePermission('incident:view')` (from `@/server/auth/dal`).
- Actions / API: `const user = await authorize('incident:update', incident.regionId)` — throws `AuthError(401|403)`.
- API routes: wrap with `api(async (req, ctx) => …)` from `@/server/http` (maps Zod/Auth/Http errors to JSON). Validate input with Zod. Use `rateLimit(key, n, windowMs)` on mutating/public endpoints.
- Scope lists by region: `scopesFor(user.assignments, perm)` returns region paths (null = nationwide); filter with `regions.path LIKE scope || '%'`.
- Audit every mutation: `audit(db, { actor: user, action: 'incident.status_change', entityType: 'incident', entityId, regionId, before, after })`.

## Data trust rules (non-negotiable)
- Every value shown must be traceable to a `data_kind` (`observed` · `reanalysis` · `nwp_forecast` · `model_forecast` · `simulated`) and a source. Render `<ProvenanceBadge kind source updated />` next to charts, maps and metrics.
- Never present CLIMATIQ output as official. Use `<OriginTag origin="climatiq" />`. Official warnings only appear if retrieved from a verifiable source (currently none — say so).
- Simulated/demo data must be visibly labelled (`<DemoTag />`, dashed provenance badge).
- Severity is never colour-only: use `<SeverityBadge />` (icon + text). Confidence is a heuristic, never call it a probability.
- Do not imply city precision: cities show their district forecast with `resolution` displayed.

## Scenarios
`currentScenario()` (`@/server/scenario`) returns `'live' | 'replay'` from a cookie. Replay = real ERA5 data for the late-May 2024 heatwave with CLIMATIQ hindcasts issued as of `REPLAY.issuedFor` (2024-05-26). Use `latestRun(db, scenario)` and the helpers in `@/server/forecasting/queries.ts`. Live may have no run if Open-Meteo is unreachable — show an informative empty state.

## UI kit (`@/components/ui/*`)
`Panel`, `MetricCard`, `PageHeader`, `Button`, `LinkButton`, `buttonClass`, `Field`/`Input`/`Select`/`Textarea`, `EmptyState`, `ErrorState`, `Skeleton`, badges (`SeverityBadge`, `ProvenanceBadge`, `ConfidenceBadge`, `OriginTag`, `DemoTag`). Tailwind tokens: `bg-bg`, `text-fg`, `text-fg-muted`, `text-accent`, `bg-wine`, `text-sand`, `border-line`, `glass`, `glass-strong`, severity vars `var(--sev-high)` etc. Fonts: `font-display` (Orbitron, brand/hero/metrics), `font-heading` (Space Grotesk), `font-sans` (Inter), `font-mono`.
Light Sand is the default theme; check dark mode (`[data-theme=dark]`). Respect `prefers-reduced-motion` (`useReducedMotion` from `motion/react`; GSAP: check `matchMedia`). Accessibility: semantic landmarks, labels, keyboard support, visible focus, table alternatives for maps/charts.

## Database
Schema: `src/server/db/schema.ts`; migrations in `drizzle/` are generated by the lead only (**do not edit the schema or generate migrations** — request changes instead). Seeds: `src/server/db/seed/*` with idempotent steps registered in `seed/index.ts`.
